# Local Radar backend (installation assets only)

This directory defines the repository side of the `Vercel UI + local Radar/Hermes backend` topology. Committing these files does not install, start, migrate, seed, tunnel, or deploy anything.

Safety invariants:

- The database is exactly `xiuqiu_radar`, reached through an absolute PostgreSQL Unix socket by the runtime `pg` driver. It is neither Neon nor the Article Catalog database.
- Public read traffic binds only `127.0.0.1:4320`; Hermes claim/ack binds only `127.0.0.1:4321`. Both require HMAC, timestamp, nonce and replay protection. Only port 4320 may appear in the named-tunnel template.
- Local workers force `RADAR_LOCAL_BACKEND=true`, which disables Qiu Market and rejects an override that tries to re-enable it. No wallet, funds or trade path exists here.
- Learning v2 pages continue to render committed Git snapshots. The compatibility API does not become UI authority.
- The digest launcher checks Shanghai wall time every five minutes, runs after 08:00 on boot/wake, and writes its daily success marker only after both idempotent workers succeed.
- Logs are rotated only from exact Radar, Content and the two named Hermes log roots with fixed filename allowlists; symlinks and non-regular files fail closed. Content includes API, PostgreSQL and tunnel logs. Hermes includes gateway, agent, error, shutdown/exit/faulthandler diagnostics, plus the primary Learning dispatcher log. Only each configured Hermes home's `cache/terminal-output` directory is pruned, to 100 regular files and 14 days; other profiles and Qiu paths are rejected. Test cleanup only signals PIDs from allowlisted pid files whose command contains this directory and `--test-fixture`.

Controlled installation checklist (run by the release owner, not by repository tests):

1. From an exact clean commit, run `node ops/local-backend/render-install.mjs` with a new absolute `--target`, the exact `--repo`, absolute `--node`/`--npm`, clean HTTPS `--page-origin`, Unix-socket `--database-url`/`--postgres-socket`, and the three audited log plus two Hermes home directories. The renderer refuses an existing target, creates independent public/internal secrets without printing them, and writes env/log/cron manifests, plists and receipt as `0600`. The audited Content root is `/Users/xiuqiu/Library/Logs/XiuqiuContent`; its expected names are `api`, `api.error`, `postgres`, `postgres.error`, `tunnel`, and `tunnel.error` with `.log`. Named-tunnel flags are optional as a complete group; partial values fail closed and no tunnel is invented.
2. Create a dedicated local role/database (`xiuqiu_radar_app` / `xiuqiu_radar`) on the existing Content PostgreSQL Unix socket. Do not grant access to `xiuqiu_content` and do not set a Neon URL. Live-audited companion labels are `com.xiuqiu.content.api`, `com.xiuqiu.content.postgres`, `ai.hermes.gateway`, and `ai.hermes.gateway-radar-secondary`; keep these as explicit environment values so a future rename reports `configured=false/loaded=false` instead of guessing.
3. Install production dependencies and prove `node -e "import('pg').then(() => console.log('pg-runtime-ok'))"` succeeds with development dependencies omitted. The repository smoke produced `pg-runtime-ok` from `npm ci --omit=dev --ignore-scripts`, with no `@vitejs/plugin-vue` installed.
4. Run `RADAR_DATABASE_DRIVER=pg MARKET_RADAR_DATABASE_URL="$RADAR_LOCAL_DATABASE_URL" npm run market-radar:migrate` twice. Require 001–012 checksum pass and a real Unix-socket integration test before workers start. From the same exact clean commit, source the rendered environment and run `npm run radar:publish-local-git-snapshots -- --repo '<exact repo>' --dates 'YYYY-MM-DD'`; dates are always explicit. This publisher uses the `pg` Unix-socket adapter, reuses the Learning v2/Market validation and research-publication builders, rejects dirty/untracked Git or fixture/local-engineering content, records exact HEAD in `source_revision`, and never invokes the Neon adapter. In an isolated `xiuqiu_radar` fixture, prove both digest workers bind the same current published snapshot into digest and outbox, internal claim/ack writes one delivery receipt, retry remains idempotent, and no Neon/Qiu connection occurs. Deploy the Hermes plugin/config as a separate explicit step, setting its API origin exactly to `http://127.0.0.1:4321` and page origin to the accepted HTTPS site; the renderer intentionally does not mutate existing Hermes profiles.
5. Before loading the digest timer for the first time, check Shanghai time. If it is already 08:00 or later and today's message was delivered by the old path, first verify the actual remote provider receipt, then run `node ops/local-backend/digest-handoff.mjs --verified-receipt-id '<verified receipt id>'` with the rendered environment sourced. This stores only a SHA-256 receipt hash in a `0600` marker and prevents an automatic duplicate catch-up. Never create this marker without a verified remote delivery receipt; if no receipt exists, let the idempotent catch-up run.
6. Rendered labels must not collide with existing labels. Confirm the existing Content PostgreSQL/API and both Hermes launchd jobs have live-audited KeepAlive/recovery semantics before loading the new Radar assets. Then load the two APIs, independent `caffeinate`, worker timers, digest catch-up and log rotation. The Radar API pools use at most two connections each with bounded idle/connection timeouts. Confirm PID, CPU, RSS and bound ports with `run-service.sh status`.
7. Create (do not guess) a Cloudflare named tunnel and a fixed hostname. Render `config.yml.template`; the single ingress target must stay `http://127.0.0.1:4320`. Quick Tunnel URLs are rejected as completion evidence.
8. Set only the protected Vercel HMAC upstream variables after the fixed HTTPS health probe passes. Keep internal port 4321 absent from the tunnel and from Vercel.
9. Controlled recovery: record status, stop only one rendered launchd label, verify an explicit degraded/static Vercel response, wait for KeepAlive, then record the new PID, CPU/RSS, signed health 200 including `database=ready`, port owner, worker freshness and delivery receipt. Never use broad `pkill`.

Rollback is unloading only the rendered Radar labels, removing the Radar-only Vercel upstream variables, and restoring the previous application deployment. The independent local database is retained for forensic/retry evidence unless the user separately authorizes deletion.
