# 先把行情与交易分开

Qiu Market 的行情部分回答：资产是谁、报价来自哪里、多久以前成功过、当前还能不能作为参考。虚拟交易部分回答：订单怎样排队、资金冻结多少、成交怎样记账、提交结果未知后如何恢复。

两者可以共用一个浏览器入口，但对状态的写入职责不同。行情异常时要显式降级；虚拟交易进程不可用时，交易路径可以返回不可用，而行情页面继续工作。共享页面不代表共享账本，也不代表一个健康响应能证明整个产品正常。

> 证据边界：本文于 2026-10-24 依据已提交的架构、质量与恢复材料修订。它修正早期概念图，保留原始发布日期；本轮没有重跑服务或测试。私有源码、运行配置和版本标识不公开。

# 持久状态先落 PostgreSQL

当前行情主写顺序是：

```text
交易所 / DEX 来源
  → 身份映射、来源时间与格式校验
  → Snapshot Writer
  → PostgreSQL 持久状态
  → Redis 派生缓存 / 排行 / 心跳
  → 统一读模型 → HTTP / gRPC → Markets 页面

历史分析数据 → Doris 旁路
```

这与“先写 Redis、Worker 再同步 PostgreSQL”的早期示意不同。PostgreSQL 保存资产身份、市场配置、快照、来源与综合参考价的持久事实；Redis 保存派生值，并在一组请求的读快照中承担版本选择职责。Doris 服务历史分析，不拥有订单或资金事实。

这里的“谁说了算”要说到具体问题：持久行情由 PostgreSQL 决定；同一个时间桶里下游共同读取哪一版快照，则由 Redis 的读快照规则决定。Redis 不可用时，不能让每个 API 各自查询 SQL，然后声称它们读到了同一份快照；只有明确实现的旧查询路径可以按各自契约回退。

# 资产身份不能只看 symbol

同一个 BTC 可能出现在现货、永续合约和 AMM 路线里。统一展示需要先识别 canonical asset，再识别具体 provider market；symbol 相同不是足够证据。

综合现货价只使用合格的现货来源。永续标记价和 DEX 路线价可以有独立页面与来源信息，但不能混入综合现货价。缺少新鲜报价或必要的汇率时，展示不可用，比从另一类来源补一个看似合理的价格更准确。

来源选择与上线门也不同：选中某个资产决定页面成员；shadow、canary、enabled 等 rollout 状态决定可否正式发布。短时询价失败不能偷偷换成员，本地预览也不能自动晋级正式来源。

# 新鲜度是业务事实

判断行情时至少要分开四件事：

| 维度 | 要回答的问题 |
| --- | --- |
| 进程心跳 | 采集或 API 进程还在运行吗？ |
| 最近尝试与成功 | 来源刚尝试过，还是确实拿到合格响应？ |
| 上游事件时间 | 数据描述的是现在，还是旧时刻？ |
| 展示资格与排除原因 | 当前值能否进入读模型，为什么？ |

服务接收时间不能冒充上游事件时间。上次成功值可以保留，但必须展示年龄与 Fresh、Stale、Unavailable 状态；缓存命中也不能算作一次新的来源成功。

同样，返回空列表有不同原因：成功查询且确实没有结果，可以显示 empty；provider 在当前部署不可用，应显示 unavailable；请求还在进行中，应显示 loading。过期、失败和未知不能用空态或零价格掩盖。

# 一个浏览器入口，两个写入边界

当前架构记录中的薄 Web 入口只按路径转发：

```text
浏览器
  ├─ 行情路径 → Market API → PostgreSQL / Redis 读模型
  └─ 虚拟交易路径 → gateway → 独立交易进程
                                 → 独立交易 PostgreSQL
                                 → 只读消费合格行情参考
```

Web 入口不撮合、不持有账本，也不消除会话、Origin 或 CSRF 检查。交易进程独立恢复 event stream 与 snapshot；只有状态校验一致后才恢复接单。研究事件与质量评分只影响各自的只读展示，不能获得撮合、参考价或 Ledger 的写权限。

虚拟交易的详细资金边界见[撮合、双重记账与确定性恢复](/articles/qiu-market-virtual-funds-recovery)。

# 故障时分别报告什么

- 行情来源失败：保留允许保留的最后成功值，标注年龄、排除原因和降级状态，不生成假价格。
- Redis 读快照 authority 不可用：按该契约失败关闭，不能各读一次数据库后伪装为同版快照。
- 虚拟交易提交结果未知：停止新命令，从持久事件恢复，避免重复资金效果。
- 研究来源失败或过期：显示 degraded 或 stale；只有合格查询的零结果才显示 empty。

2026-10-17 的恢复记录提供了一个具体反例：公开行情入口的 502 已消除，但同次现场参考展示价仍不可用，市场雷达公开事件仍为空。这个历史快照说明“可以请求”“有新鲜数据”“能完成交易”需要各自验收。本轮没有重新检查这些线上状态。

# 继续验证的顺序

先固定候选与工具链，再运行隔离 full-stack golden，核对数据库、进程恢复、账本和清理回执。随后分别核对真实来源的新鲜度与许可、公开研究发布、生产交易和 Owner 解释；其中一项通过，不能替其他项签字。
