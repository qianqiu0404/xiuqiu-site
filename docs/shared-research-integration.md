# 共享研究接入

目标：保留 `xoqiu09/shared-research` 的收集与整理方式，让读者在 xiuqiu-site 的
同一套情报流、筛选、主题页和详情页阅读资料。两个账号与仓库继续独立。

## 内容与更新

1. shared-research 通过已有构建输出版本化公开索引 `feed/v1/index.json`，以及
   `feed/v1/records/<id>.json` 详情。复用原站的事件/完全重复内容分组与分类。
2. xiuqiu-site 的 `/research-data/*` 只读代理到这一固定公开目录；浏览器不访问
   GitHub，不需要 token，不开启跨仓库写权限，不新增定时任务。
3. 首页加载原有静态雷达，同时读取共享研究，按内容日期合并。五分钟内复用内存缓存，
   过期重新读取；源站每次 main 发布后，读者刷新即可获取，不需重新发布个人站点。
4. 每条资料使用 `/research?id=<稳定ID>`，以原生 Vue 组件和站点样式渲染正文。
   关联资料转成站内阅读链接；原始来源和原站保留可点击入口。

## 阅读边界

- 日期保留事件日/原文发布日期；缺少时明确显示“收录日期”。构建时间不作为新闻日期。
- 原有雷达和共享资料分别展示更新情况，不以资料源的新记录掩盖雷达的过期状态。
- 来源访问状态、模型输出类型和核实范围分开显示，不把“能读原文”当作“事实已证实”。
- 新闻接口只接入正式资料、事件与日报/周报；示例、规则、提示词和批次不加入新闻。
- 去重复用源站明确的事件关联或完全相同内容。两侧同链接/相近标题不能证明同一事实，
  不跨来源擅自合并，不删除资料源的任何原始记录。资料源分组保留所有材料入口。
- 订阅区注明原有 Radar RSS/JSON/API 的覆盖范围；这些冻结契约保持原样。
  共享研究详情暂时 noindex，沿用资料源的索引边界，不把全部资料加入 sitemap。
  固定阅读入口和五个研究分类各自生成静态入口页；未知路径继续保留原来的 HTTP 404，
  不增加 SPA 兜底重写。未知资料 ID 在固定入口显示“没有找到这条资料”。

## 失败与安全

索引和详情校验版本、ID、日期、来源域名与链接。正文只接受白名单文本树，不使用
`v-html`。每次请求十秒超时、最多 2 MiB，限制正文深度和节点数。缓存只存在内存。
接口失败时显示重试按钮及原站入口；已载入资料和原有雷达继续可读。不把失败显示为空库。
空库与未知资料链接各有独立状态。

## 验证和发布

源站：两组知识库检查、`test_public_feed.py`、完整静态构建。
个人站点：现有 `npm run build` 包含新增行为测试，不更改冻结的 build/工作流。
本地联合验证：先运行源站 HTTP 服务；给 Vite 的 `RESEARCH_PREVIEW_ORIGIN` 指向
该服务，检查首页、领域/来源/主题/搜索、深链接、站内关联、断网/空库/错误状态、
桌面与 375px 以及深浅主题。Vite preview 复用同一代理配置。

两个维护 PR 分别评审，先发布源站接口，再发布消费方。源站 main 由原 Git 集成发布；
个人站点生产只走现有 `release-controller.yml`，不改 Git 自动部署设置。
源站脚本改动须维护者审阅。该 Release Controller 还包含数据库迁移、通知和 Market
worker，网站可预览不代表这些生产环节已执行或获得额外授权。

回滚：消费方回滚本次 PR 即恢复原雷达界面，源站 API 可继续存在；需要时再回滚
源站维护 PR。无需回滚研究记录、迁移仓库或修改采集 Bot。
