# 内容维护与发布

2026-10-24 恢复：学习雷达、市场研究与Grok快讯分别生产。日常研究由本机Codex固定聊天主Agent协调，在完成来源、候选与测试审阅后批准发布。该安排来自用户明确委托，不代表用户本人已验收内容或掌握技术。

## 每日研究

- 每天05:30（Asia/Taipei）由同一维护任务分别创建两类runKey，复用已有结果，不重复建PR。学习沿用07:20编辑、07:35门禁、07:45快照；迟到版保留真实采集时间并标backfill。
- 学习2AI+2Web3+1专题，来源不足停止该期；市场1–5个一手事件，允许正常无新增。每条须实际阅读原文、核对日期、30日去重，事实、推断与边界分开。
- 两类数据分支保持既有automation前缀与文件白名单。先生成内容和sitemap，再完整build，避免新回顾尚未进入sitemap便运行关联测试。
- 主Agent必须审核具体候选和测试后才转正或合并，不降低校验规则。两类研究独立，不能因一类不足而编造材料。
- 每周日核对当前项目是否有新的已提交证据；只更新有事实变化的摘要，保留历史核验日、公开角色和Claim门禁。

## 发布与验收

普通内容只走Release Controller，绑定实时main完整SHA，显式保持enqueue_market_notifications=false、run_market_worker=false。学习通知继续关闭。静态快照发布不意味着运行时采集、动态事件/摘要或微信送达成功。

推广后逐一核对当期页面、研究包、订阅出口与发布指针。两个最新快照都须来自本次已审阅source；跨午夜仍使用preflight选定的研究日期。保持静态页面在API快照不同或runtime为空时的显示权。

来源ledger、具体审批、测试和线上读回留在维护任务资料，公开站只提交去敏内容与生成物。任务无变化时安静，有正式新内容、失败或必要人工行动才通知。

## 运行边界

调度依赖本机在线与应用可运行，保存调度不等于已经执行。每日任务先查幂等回执再续接。Grok Bot的新闻投递与首次自动投递复查继续沿用独立既有安排，不被本任务替代。

实时Market worker仍受AUTOMATION_READY及精确SHA授权约束；当前ingest含AI与额外数据库/通知副作用，不能当作纯采集器自动开启。实时来源过期时如实显示degraded，正常零事件不自动判故障。
